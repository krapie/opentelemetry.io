오픈텔레메트리 eBPF 계측(OpenTelemetry eBPF Instrumentation)은 서버 측
애플리케이션 코드의 전체 요청 시간을 추적할 수 있는 eBPF 기반 애플리케이션 자동
계측 도구이다.

원격 서비스 요청을 수행할 때, 클라이언트가 체감하는 응답 시간은 서버에서 측정된
응답 시간과 다르다.

다음 다이어그램은 클라이언트 관점에서 발생할 수 있는 다양한 지연을 보여준다.

![웹 서비스 요청의 수명 주기](./req-life-cycle-2.png)

- **전체 요청 시간(Total Request Time)**: 네트워크와 로드 밸런서에서 발생하는
  지연, 그리고 서비스 내부에서 소요된 시간을 포함한 클라이언트 관점의 시간이다.
- **서비스 시간(Service Time)**: 네트워크 지연과 로드 밸런서 오버헤드를 제외한
  서비스 관점의 시간이다.

서비스 시간만 모니터링하면 사용자 경험에 영향을 주는 중요한 성능 문제를 놓칠 수
있다. 예를 들어 느린 로드 밸런서, 네트워크 혼잡, DNS 확인(resolution) 문제 등이
있다.

eBPF를 사용하면 수동 계측 도구의 한계를 극복할 수 있다. OBI는 커널의
connect/receive/write/close 함수에 트레이스포인트(tracepoint)를 삽입한다(Go
애플리케이션의 경우 Go 런타임에도 삽입한다). 이 저수준 계측은 더 정확한 메트릭을
제공하며 클라이언트 관점의 요청 시간을 캡처할 수 있게 한다.

OBI는 여러 스팬으로 나뉜 트레이스를 보고한다.

![OBI 트레이스와 스팬](./server-side-trace.png)

위 이미지는 OBI가 보고하는 트레이스의 일반적인 구조를 보여준다.

- **전체 요청 시간(Total Request Time)**: 클라이언트 관점의 시간
- **서비스 시간(Service Time)**: 서비스 관점의 시간
- **SQL 시간(SQL Time)**: SQL 쿼리에 소요된 시간(해당하는 경우)

트레이스 스팬은 커널 수준에서 생성되며 클라이언트 관점의 전체 요청 시간을 캡처할
수 있다. 이를 통해 서비스 관점만으로는 보이지 않을 수 있는 문제를 식별할 수
있다.
