이 페이지는 오픈텔레메트리(OpenTelemetry) PHP Distro 사용에 따른 성능상의 영향을
개괄하고, 오버헤드를 최소화하기 위한 가이드를 제공한다.

여느 계측 에이전트와 마찬가지로, 배포판(distro)은 애플리케이션 프로세스 안에서
실행되며 런타임 비용을 추가한다. 정확한 영향은 아키텍처, 구성, 배포 환경,
워크로드에 따라 달라진다.

아래 벤치마크는 로컬 도커 환경(`PHP-FPM 8.2 + NGINX`)에서 여러 PHP
옵저버빌리티(observability) 구성을 비교한다. 컬렉터가 있는 시나리오에서는
컬렉터도 로컬에서 실행되며 호스트 CPU 자원을 공유한다.

## 벤치마크 설정 {#benchmark-setup}

- 애플리케이션: PHP-FPM 8.2의 Laravel/Aimeos
- 환경: NGINX가 포함된 로컬 도커
- 텔레메트리 대상: OTLP 호환 엔드포인트

## 결과 {#results}

| 유형                                                          | 요청당 평균 시간 \[ms\] | 오버헤드 \[ms\] |
| ------------------------------------------------------------- | ----------------------: | --------------: |
| 에이전트 없음                                                 |                   17.36 |            0.00 |
| 벤더별 APM 에이전트                                           |                   20.63 |            3.27 |
| 오픈텔레메트리 PHP Distro                                     |                   23.08 |            5.71 |
| 오픈텔레메트리 PHP Distro + 로컬 컬렉터                       |                   24.37 |            7.01 |
| 바닐라 오픈텔레메트리 PHP + protobuf(C 확장) + 컬렉터         |                   25.76 |            8.40 |
| 바닐라 오픈텔레메트리 PHP 순수 PHP protobuf 내보내기 + 컬렉터 |                   49.02 |           31.66 |
| 바닐라 오픈텔레메트리 PHP 순수 PHP protobuf 내보내기          |                 2158.58 |         2141.22 |

## 주요 결과 {#key-findings}

- 오픈텔레메트리 PHP Distro는 순수 PHP protobuf 내보내기를 사용하는 바닐라
  오픈텔레메트리 PHP에 비해 오버헤드를 크게 줄인다.
- 로컬에 컬렉터를 배치하면 PHP 워커와 CPU를 두고 경합할 때 오버헤드가 증가할 수
  있다.
- 바닐라 오픈텔레메트리 PHP의 순수 PHP protobuf 내보내기는 이 벤치마크에서 매우
  높은 오버헤드를 유발한다.

## 권장 사항 {#recommendations}

- 자신의 워크로드와 인프라에서 오버헤드를 측정한다.
- 비동기 트랜스포트와 함께 OTLP HTTP/protobuf를 우선 사용한다.
- 무거운 컬렉터 워크로드를 지연에 민감한 애플리케이션 워커와 같은 위치에 두지
  않는다.
- SLO를 충족하도록 샘플링과 익스포터 설정을 조정한다.
