## 오픈텔레메트리 API 및 SDK 가져오기 {#import-the-opentelemetry-api-and-sdk}

먼저 서비스 코드에 오픈텔레메트리(OpenTelemetry)를 가져와야(import) 한다. 실행
가능한 바이너리에서 사용될 라이브러리나 다른 구성 요소를 개발하는 경우라면,
API에만 의존성을 가지면 된다. 산출물(artifact)이 독립 실행형(standalone)
프로세스나 서비스인 경우라면, API와 SDK 모두에 의존성을 가져야 한다.
오픈텔레메트리 API 및 SDK에 대한 자세한 내용은 [명세](/docs/specs/otel/)를
참고한다.

## 오픈텔레메트리 API 구성하기 {#configure-the-opentelemetry-api}

트레이스 또는 메트릭을 생성하려면, 먼저 트레이서 프로바이더(Tracer Provider)
및/또는 미터 프로바이더(Meter Provider)를 생성해야 한다. 일반적으로 SDK가 이러한
객체에 대해 단일 기본 프로바이더를 제공하는 것이 권장된다. 그런 다음 해당
프로바이더로부터 트레이서 또는 미터 인스턴스를 가져와, 이름과 버전을 지정한다.
여기서 선택하는 이름은 정확히 무엇이 계측되고 있는지를 식별해야 한다. 예를 들어
라이브러리를 작성하는 경우라면, 생성되는 모든 스팬이나 메트릭 이벤트를
네임스페이스(namespace)로 구분할 수 있도록 라이브러리 이름을 따서 이름을
지정해야 한다(예: `com.example.myLibrary`). 또한 라이브러리나 서비스의 현재
버전에 해당하는 버전 문자열(예: `semver:1.0.0`)을 함께 제공하는 것이 권장된다.

## 오픈텔레메트리 SDK 구성하기 {#configure-the-opentelemetry-sdk}

서비스 프로세스를 구축하는 경우라면, 텔레메트리 데이터를 분석 백엔드로 내보내는
데 적합한 옵션으로 SDK도 구성해야 한다. 이 구성은 설정 파일이나 다른 메커니즘을
통해 프로그래밍 방식으로 처리하는 것이 권장된다. 활용할 수 있는 언어별 튜닝
옵션도 있다.

## 텔레메트리 데이터 생성하기 {#create-telemetry-data}

API와 SDK를 구성하고 나면, 프로바이더로부터 얻은 트레이서 및 미터 객체를 통해
트레이스와 메트릭 이벤트를 자유롭게 생성할 수 있다. 의존성에 대해서는 계측
라이브러리를 활용한다. 이에 대한 자세한 내용은
[레지스트리](/ecosystem/registry/)나 사용 중인 언어의 저장소를 확인한다.

## 데이터 내보내기 {#export-data}

텔레메트리 데이터를 생성했다면, 이를 어딘가로 전송하고 싶을 것이다.
오픈텔레메트리는 프로세스에서 분석 백엔드로 데이터를 내보내는 두 가지 주요
방법을 지원한다. 프로세스에서 직접 내보내거나,
[오픈텔레메트리 컬렉터](/docs/collector)를 통해 프록시(proxy)하는 방법이다.

프로세스 내(in-process) 내보내기를 사용하려면, 오픈텔레메트리의
인메모리(in-memory) 스팬 및 메트릭 객체를 Jaeger나 Prometheus와 같은 텔레메트리
분석 도구에 적합한 형식으로 변환해주는 라이브러리인 하나 이상의
_익스포터(exporter)_ 를 가져와서 의존성을 가져야 한다. 또한 오픈텔레메트리는
모든 오픈텔레메트리 SDK가 지원하는 `OTLP`라는 와이어 프로토콜(wire protocol)을
지원한다. 이 프로토콜은 서비스 인스턴스의 프록시나 사이드카(sidecar)로
실행되거나 별도의 호스트에서 실행될 수 있는 독립 실행형 바이너리 프로세스인
오픈텔레메트리 컬렉터로 데이터를 전송하는 데 사용할 수 있다. 이후 컬렉터는 이
데이터를 원하는 분석 도구로 전달하고 내보내도록 구성할 수 있다.

Jaeger나 Prometheus와 같은 오픈소스 도구 외에도, 오픈텔레메트리로부터 텔레메트리
데이터를 유입(ingest)하는 것을 지원하는 회사가 점점 늘어나고 있다. 자세한 내용은
[벤더](/ecosystem/vendors/)를 참고한다.
