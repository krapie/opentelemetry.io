참조 애플리케이션의 목적은 오픈텔레메트리(OpenTelemetry) SDK가 존재하는 모든
언어로 구현할 수 있는 표준화된 샘플 애플리케이션을 만드는 것이다.

## 일반 요구사항 {#general-requirements}

- 참조 앱(Reference App)의 구현은 오픈텔레메트리 API 및 SDK를 구현하는 언어별
  SIG가 담당한다. 이를 통해 애플리케이션이 해당 언어 생태계의 모범 사례(best
  practice)를 따르도록 보장하며, 애플리케이션을 어떻게 계측해야 하는지에 대한
  청사진(blueprint)을 제공할 수 있다.
- 애플리케이션에는 계측되지 않은(uninstrumented) 버전과 계측된(instrumented)
  버전이 모두 있어야 한다. 이는 opentelemetry.io의 "시작하기" 가이드에서
  오픈텔레메트리가 적용되지 않은 앱을 완전히 계측된 앱으로 전환하는 과정에서
  사용된다.
- 애플리케이션이 두 버전 모두에서 빌드되고 실행되는지 검증하는 언어별 CI 액션이
  있어야 한다.
- 애플리케이션은 명령줄 인터페이스(command line interface)에서 실행할 수 있어야
  한다.
- 애플리케이션을 컨테이너화된(containerized) 환경에서 실행하기 위한 Dockerfile이
  있어야 한다.
- 애플리케이션은 독립적으로 실행되어야 한다. 즉, 이를 포함하는 저장소의 다른
  콘텐츠에 하드 의존성(hard dependency)을 가질 수 없다. 이를 통해 사용자는
  의존성 관리를 풀어낼 필요 없이 코드를 자신의 프로젝트로 복사해 사용할 수 있다.

## 서비스 요구사항 {#service-requirements}

- 애플리케이션은 기본적으로 8080 포트에서 HTTP 요청을 수신 대기(listen)해야
  한다. 포트는 환경 변수 APPLICATION_PORT를 통해 설정할 수 있어야 한다.
- HTTP 요청을 처리하기 위해서는 계측 라이브러리가 존재하는 라이브러리를 사용해야
  한다. 애플리케이션은 `GET`(그리고 선택적으로 `POST`)을 통해
  `/rolldice?rolls=<n>` 엔드포인트를 제공해야 하며, 다음과 같은 HTTP 상태 코드와
  JSON 결과를 반환해야 한다.
  - `rolls`가 설정되지 않았거나 유효한 입력값(0보다 큰 양의 정수)을 가지는 경우:
    상태 코드 `200`과 함께, `rolls`가 설정되지 않았거나 1인 경우에는 1과 6
    사이의 단일 숫자를, 그렇지 않으면 `rolls`의 값인 `n`개의 1과 6 사이의 숫자로
    이루어진 배열을 반환한다.
  - `rolls`에 유효하지 않은 입력값(숫자가 아님)이 설정된 경우: 상태 코드 `400`과
    `{"status": "error", "message": "Parameter rolls must be a positive integer"}`를
    반환한다.
  - `rolls`에 `0` 또는 음의 정수가 설정된 경우: 상태 코드 `500`을 반환하며 JSON
    출력은 없다. 이 오류 예시는 오픈텔레메트리를 사용해 오류를 식별하는 방법을
    보여주는 데 사용된다.
- `/rolldice` 엔드포인트에는 선택적 속성 `player=name`이 있을 수 있다.
- 애플리케이션은 다음 로그 라인을 출력해야 한다.
  - 상태 코드가 `<400`인 각 HTTP 요청에 대한 INFO 레벨 메시지
  - 상태 코드가 `400`에서 `499` 사이인 각 HTTP 요청에 대한 WARN 레벨 메시지(JSON
    결과로 전송될 메시지 포함)
  - 상태 코드가 `499`보다 큰 각 HTTP 요청에 대한 ERROR 레벨 메시지
  - 선택적 속성 `player`가 설정된 경우, `player`의 값과 굴려진 숫자를 출력하는
    DEBUG 레벨 메시지
  - 선택적 속성 `player`가 설정되지 않은 경우, 정적 값 `anonymous player`와
    굴려진 숫자를 출력하는 DEBUG 레벨 메시지. 이 로그 라인들은 계측 과정에서
    로그 브리지(log bridge)를 추가하여 오픈텔레메트리가 기존 로깅 프레임워크와
    어떻게 연결될 수 있는지 보여주는 데 사용된다.
- 애플리케이션의 코드는 두 개의 파일로 분리되어야 한다.
  - HTTP 요청 처리를 담당하는 `app` 파일
  - 주사위 굴리기 함수의 구현을 담당하는 `library` 파일. 이 파일들의 이름은
    `app.js`, `roll-the-dice.js`처럼 구현 언어에서 관용적으로(idiomatic)
    사용하는 방식이어야 한다. 중요한 점은 이 둘을 분리함으로써, `library`는 오직
    API에만 의존하고 모든 SDK 코드는 `app` 코드에서 초기화된다는 것을 코드로
    보여준다는 것이다.
- `rolls`에 대한 오류 처리는 다음과 같이 분리되어야 한다.
  - `app`은 `rolls`가 정의되어 있는지 확인하고, 정의되어 있지 않으면 `1`로
    설정한다.
  - `app`은 `rolls`가 숫자인지만 확인한다. 숫자이면 `library`에서 주사위를
    굴리는 함수를 호출한다. 숫자가 아니면 `400` 오류로 오류 처리를 수행한다.
  - `library`는 `rolls`가 양수인지 확인한다. 양수가 아니면 예외(exception)를
    던진다. `app`은 이 오류를 캐치(catching)하여 `500` 오류를 반환한다.
- `library`에는 위에서 설명한 오류 처리를 수행하는 외부 함수(outer function)가
  있어야 한다. 그런 다음 외부 함수는 `rolls`의 값에 따라 다음을 수행한다.
  - `rolls == 1`: 내부 함수(inner function)를 한 번 실행하고 그 값을 반환한다.
  - `rolls > 1`: 내부 함수를 `rolls`번 호출하는 루프를 실행하고 그 결과를 배열로
    반환한다.
- `library`의 내부 함수는 1과 6 사이의 무작위 숫자를 생성하고 그 값을 반환한다.

## 계측 요구사항 {#instrumentation-requirements}

- 가능하다면, 오픈텔레메트리 SDK의 초기화는 별도의 파일에 담아 `app` 파일에서
  가져와야(import) 한다. 그렇지 않다면 `app` 파일의 일부여야 한다.
- 초기화 과정에서 `process`, `container`, `os` 등과 같은 일반적인 리소스
  감지기를 로드해야 한다.
- "lib" 파일은 오픈텔레메트리 API에만 의존해야 한다.
- `service.*` 속성은 환경 변수(`OTEL_SERVICE_NAME`,
  `OTEL_RESOURCE_ATTRIBUTES`)를 통해 추가되어야 한다.
- 그 외의 `resource detectors`는 SDK 초기화에 추가되어야 한다.
- 텔레메트리를 내보내기 위해 애플리케이션은 `stdout`/`console` 및 `otlp`용
  익스포터를 사용해야 한다.
- 오픈텔레메트리 구성 요소에 대한 진단 로깅(diagnostic logging)을 활성화하는
  옵션이 있어야 하며, 이상적으로는 `OTEL_LOG_LEVEL`을 통해 구현되어야 한다.
- 사용 중인 HTTP 라이브러리를 위한 계측 라이브러리를 추가할 방법이 있어야 한다.
  이 계측 라이브러리는 HTTP에 대한 안정된(stable) 시맨틱 컨벤션을 사용해야 한다.
  가능하면 대부분의 시그널을 커버하는 라이브러리를 선호하며, 이상적으로는
  트레이스와 메트릭을 모두 갖춘 라이브러리가 좋다.
- 계측 라이브러리를 사용할 수 없는 경우에 한해, `/rolldice` 엔드포인트를
  처리하는 `app`의 함수는 사용자가 스팬과 메트릭을 추가하여 직접 계측한다.
- 사용 중인 로깅 메커니즘을 위한 로그 브리지가 있어야 하며, 이를 통해 모든
  로그가 자동으로 수집(collect)되고 내보내져야(export) 한다.
- `library`의 외부 함수에 대해 생성되는 스팬이 있어야 한다. 이 스팬은 함수의
  실행 시간을 추적한다. 예외가 발생하면 이를 기록한다. `rolls`의 값, `code.*`
  등과 같은 속성을 스팬에 추가한다.
- `library`의 내부 함수에 대해 생성되는 스팬이 있어야 한다. 이 스팬은 함수의
  실행 시간을 추적한다. 생성된 무작위 숫자를 속성으로 스팬에 추가한다.
- `library` 파일에서는 다음 메트릭이 생성되어야 한다.
  - 외부 함수 호출 횟수를 위한 Counter(카운터)
  - 결과값(1-6) 분포를 위한 Histogram(히스토그램)
  - `rolls`의 마지막 값을 위한 Gauge(게이지)
